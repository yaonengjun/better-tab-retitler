# Tab ReTitler 核心修改总结

本文档记录了为解决 `tab-retitler` 插件在诸如 `dongmonitor.jd.com` 等强侵入性单页应用（SPA）中修改标题失效、引起页面卡死及闪烁问题而进行的系列重构与修复。

## 一、 面临的挑战与问题

在现代 SPA 框架（如 Vue + micro-app）中，页面脚本会频繁且强制地覆盖 `document.title`。这暴露了原插件在设计上的几个致命缺陷：

1. **Observer 监听脱落与内存泄漏**：
   原版 `content.js` 在检测 `<title>` 元素移除时，使用了错误的 `!document.querySelector('title')` 判断逻辑。当 SPA 瞬间替换（Remove & Add）标签时，该判断永远为假，导致监听器留在已被移出 DOM 的旧节点上失效。此外，原版清理逻辑 `cleanupObservers()` 存在逻辑死锁，每次重新挂载监听器时都会遗留旧的实例，最终导致 Observer 指数级爆炸和严重的内存泄漏。
2. **微任务无限死循环 (页面假死)**：
   在最初尝试用纯事件驱动的方式对抗 SPA 强制覆盖时，出现了“插件设为 A -> 页面立马改回 B -> 触发插件改回 A -> 触发页面改回 B”的死循环。由于 `MutationObserver` 是以微任务（Microtask）的形式执行的，这种高频争夺瞬间塞满了浏览器的微任务队列，导致主线程卡死，页面彻底失去响应。
3. **视觉闪烁 (Flicker)**：
   即使加入了延迟（Debounce）防卡死机制，DOM 的来回修改依然会导致浏览器顶部的标签页名称出现可被肉眼感知的闪烁或切换。

## 二、 解决方案与代码重构

为了彻底、优雅地解决上述问题，我们采取了从上层 DOM 到下层 V8 引擎运行环境的多维度的防御机制。

### 1. 修复监听器脱落与防抖防卡死 (修改 `content.js`)
* **精准 DOM 追踪**：弃用 `querySelector` 判断，直接扫描 `MutationRecord` 中的 `addedNodes` 和 `removedNodes` 寻找 `<title>` 元素。只要有标题相关的节点变更，立即精准重载监听。
* **修复清理机制**：摒弃了带有逻辑死锁的 `isCleanedUp` 状态标志。在每次挂载新监听器前，强制对已有的 `titleObserver` 和 `headObserver` 执行 `disconnect()`，彻底消除了内存泄漏和级联爆炸的隐患。
* **引入防抖保护锁**：在 `titleObserver` 触发的反制逻辑中，引入了 `setTimeout(..., 10ms)` 的防抖（Debounce）处理。这强行将反制动作降级为宏任务（Macrotask），让事件循环得以呼吸，彻底杜绝了微任务死循环导致的页面假死。

### 2. MAIN World 终极拦截技术 (修改 `background.js` 与 `content.js`)
为了实现零闪烁（Zero-Flicker），我们必须在 SPA 框架动手前“防患于未然”。
* **底层劫持**：在 `background.js` 下发设置标题指令前，利用 Manifest V3 的特性，通过 `chrome.scripting.executeScript({ world: "MAIN" })` 向页面的主运行环境注入了一段高权限的隐形拦截代码。
* **静默丢弃**：该拦截代码通过 `Object.defineProperty` 劫持了原生 `document.title` 的 Setter。当页面内部 JS 试图修改标题时，拦截器会检查 `<html data-tabRetitlerLock="xxx">` 上的锁定标记。如果当前处于锁定状态，拦截器会**直接丢弃页面的修改请求**，不让它触碰底层 DOM。
* **状态欺骗**：为防止 Vue 等框架因读不到自己设定的标题而报错崩溃，拦截器中的 Getter 会返回一个“虚拟标题”（Virtual Title）安抚框架，做到了神不知鬼不觉。

## 三、 总结

通过上述改动：
- 插件对复杂 SPA 的兼容性得到了企业级提升。
- 采用事件驱动与原生劫持代替主动轮询（`setInterval`），实现了极致的**零 CPU 损耗**。
- 不管页面的 JS 有多“激进”，最终用户只能看到坚如磐石的自定义标题，不再有卡死，不再有闪烁。
