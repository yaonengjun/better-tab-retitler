# 新需求：规则增加编号 (ID)

## 需求说明
1. **新增编号字段**：每个持久化规则在保存时，新增一个编号字段（`id`），生成规则为创建时的精确时间，格式为 `yyMMdd-HHmmss`（例如：`250105-080203`，代表 2025年01月05日08点02分03秒）。
2. **Options 页面展示调整**：在 Options 页面的 "SaveTitle"（已保存的标题规则）列表中，为每个规则展示这个编号。同时将「编辑」和「删除」按钮移动到编号旁边。
3. **支持手动修改**：允许用户在 Options 页面对该编号进行二次编辑和修改。
4. **规则排序**：所有的持久化规则展示时，统一根据该编号进行排序。如果存在历史遗留没有编号的规则，可以赋予默认或垫底的排序优先级。
5. **Popup 高亮命中规则**：在“Change Tab Title”的弹窗中，如果当前 URL 已经命中了某个持久化规则，需用蓝色加粗字体把该规则的编号高亮显示出来（例如在“原始：”标题附近显示）。
   - **UI微调**：使 Original 标题和 Matched Rule 之间紧凑显示，消除多余的空行。
6. **Options 页面布局微调**：将规则列表项中的 编号、编辑按钮、删除按钮 从最右侧移动到规则框内的第一行（位于 Pattern 那一行的上方）。

---

## 改动方案 (Implementation Plan)

### 1. 数据结构变更
目前规则在 `chrome.storage.sync` 中的存储格式为：
`"key": { "title": "xxx" }`

需变更为：
`"key": { "title": "xxx", "id": "250105-080203" }`

### 2. 代码修改模块

#### 2.1 辅助函数：生成 ID
在 `background.js` 和 `options.js` 中新增一个生成 ID 的函数（或合并公共逻辑）：
```javascript
function generateRuleId() {
  const now = new Date();
  const yy = String(now.getFullYear()).slice(-2);
  const mm = String(now.getMonth() + 1).padStart(2, '0');
  const dd = String(now.getDate()).padStart(2, '0');
  const hh = String(now.getHours()).padStart(2, '0');
  const min = String(now.getMinutes()).padStart(2, '0');
  const ss = String(now.getSeconds()).padStart(2, '0');
  return `${yy}${mm}${dd}-${hh}${min}${ss}`;
}
```

#### 2.2 `background.js` 改动
- 修改 `saveTitle` 函数：
  当保存持久化规则（如 `exact`、`domain`、`keyword`、`prefix`）时，额外生成并保存 `id` 属性。
  对于临时锁定（`tablock`，键名 `Tab#...`），因为不属于持久化规则，可不生成 ID。

#### 2.3 `options.js` 改动
- **添加规则时生成 ID**：在 `addUrlPattern` 中，新增 URL 匹配规则时需要附带 `id: generateRuleId()`。
- **UI 渲染调整 (`loadSavedTitles`)**：
  - **排序逻辑修改**：目前代码中的排序是按照规则类型（域名、精确、临时等）及字母表排序。修改为：优先提取规则对象内的 `id` 进行字典序/时间先后排序；对于没有 `id` 的老规则（或 `Tab#` 临时规则），可以排在列表最后。
  - **DOM 结构调整**：为了响应新布局需求，将原本横向排列的 `.title-item` 修改为竖向布局（`flex-direction: column`），在内部最上方新增一个 Header 容器。
  - **操作按钮区域**：将 规则编号（`rule-id-display`）、编辑按钮、删除按钮 放置于新增加的 Header 容器中，使其整体位于 Pattern/URL 信息的上方。
- **二次修改 ID 逻辑**：
  - 在每个规则旁边新增一个「修改编号」的操作按钮（或允许直接点击编号文本进行编辑）。
  - 点击后，通过 `prompt` 获取用户输入的新编号，并更新到 `chrome.storage.sync` 中对应键的对象内：`update[key] = { title: value.title, id: newId }`，随后触发重新渲染列表。

#### 2.4 CSS 样式调整 (`options.css` & `popup.css`)
- **`options.css`**：调整 `.title-item` 为垂直布局，并新增头部栏的样式，使 ID 和操作按钮显示在第一行。
- **`popup.css` & `popup.html`**：解决 Popup 中空行过多的问题，主要是隐藏未使用的元素（如空的 bookmarkTitle），并利用 CSS 的 `margin` 或 `gap` 调整使 Original 和 Matched Rule 的间距紧凑。

#### 2.5 `background.js` 新增查询接口
- 增加处理来自 popup 的消息（例如 `getMatchedRule`）：
  接收当前 tab 的 URL，复用 `checkAndUpdateTitle` 中的匹配规则逻辑，将匹配到的规则对象（包含 `title` 和新增的 `id`）通过 `sendResponse` 返回。

#### 2.6 `popup.html` 与 `popup.js` 弹窗高亮显示
- **`popup.html`**：在“原始标题”区域（`<div id="originalTitleContainer">` 或类似位置）旁预留一个容器，例如 `<div id="matchedRuleInfo" style="color: blue; font-weight: bold; display: none; margin-top: 5px;"></div>`。
- **`popup.js`**：弹窗初始化（`DOMContentLoaded`）加载到当前 tab 信息后，向 background 发送 `getMatchedRule` 消息。如果背景脚本返回了匹配的规则并且该规则具有 `id`，则在界面上填充“当前命中规则编号：[ID]”等文案，并使其展示。

## 执行前确认与兼容性考虑
1. **历史规则兼容**：对于已经保存但尚未带有 `id` 字段的老规则，我们在渲染时不显示 `id` 或是显示特殊占位符。在用户手动编辑标题或者我们提供按钮时，可以补充该 `id`，排序时将无 `id` 规则置于最底部。
2. **临时标签规则过滤**：如前所述，生命周期短的 `Tab#` 规则不生成和展示 `id`，以严格契合“持久化规则”的要求。
