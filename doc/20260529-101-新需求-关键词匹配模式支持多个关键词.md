# 需求分析：关键词匹配模式支持多关键词

## 1. 需求可行性
**是否能支持使用多个关键词匹配？**
**结论**：完全可以支持。
**实现思路**：只需在保存和匹配规则时，对用户输入的关键词字符串进行分隔符拆分。当检测到网页的 URL 时，遍历拆分后的关键词列表，必须满足 URL 包含其中的所有关键词（即 AND 逻辑），即可判断该匹配规则生效，从而执行修改页面标题的操作。这更符合组合定位页面的实际需求。

## 2. 分隔符的选择及 URL 中逗号的支持情况

**输入时用什么方式隔开比较好？逗号可以吗？**
逗号是可以的，并且在日常交互设计中，它是最常见、也最符合用户直觉的多值分隔符。

**HTTP URL 中是否支持逗号？**
是的，HTTP URL 是支持逗号的。
根据 URL 标准规范（RFC 3986），逗号 `,` 属于保留字符（Reserved Characters）中的 sub-delimiters。在 URL 的 Path 或 Query 参数中，逗号可以不经过转义（`%2C`）而直接存在。例如：`https://example.com/api?tags=apple,banana` 这是一个完全合法的 URL。

**使用逗号作为分隔符带来的影响：**
如果单纯将逗号作为多个关键词的分隔符，会导致一个边界问题：**如果用户恰好想匹配一个原本就带有逗号的完整字符串片段，该片段会被直接拆分成两个不同的关键词**。

尽管在实际使用中，用户通常提取的是域名或路径中的特征英文字母、中文等，极少需要刻意匹配包含逗号的片段，但为了设计的严谨性，以下是几种常见的分隔符方案及对比：

### 分隔符方案建议

1. **方案 A：使用逗号 `,`（推荐，用户体验最好）**
   - **优点**：最符合普通用户的输入习惯，学习成本极低。为了更好的兼容性，还可以同时支持英文逗号 `,` 和中文逗号 `，`。
   - **缺点**：用户无法直接将包含逗号的 URL 片段作为一个整体来进行匹配。
   - **改进**：大多数场景下这种缺点可以忽略不计。如果必须支持，可以在程序中引入转义机制（如 `\,`），或者明确告知用户该模式下关键词不能包含逗号。

2. **方案 B：使用竖线 `|`（推荐，技术严谨度最高）**
   - **优点**：在正则表达式等编程范式中，`|` 本就代表“或”（OR）的意思。更为重要的是，`|` 在 HTTP URL 规范（RFC 3986）中既不属于保留字符，也不属于非保留字符，而是属于**不合法/不安全字符（Unsafe Character）**。这意味着在标准合规的 URL 中，竖线是**不支持明文存在**的，它必须被转义为 `%7C`。现代浏览器（如 Chrome）在底层 API 中提取到的 URL，一旦包含 `|` 都会自动转义成 `%7C`。因此，使用 `|` 作为分隔符，可以**100% 绝对严谨地避免与真实的 URL 原文产生字符冲突**。
   - **缺点**：对于非技术用户可能存在一定的认知门槛。

3. **方案 C：使用空格 ` `**
   - **优点**：输入体验极佳，用户在习惯上（如使用搜索引擎）早已适应空格作为分词符。更关键的是，**空格和竖线一样，在 HTTP URL 规范中同样是不安全/不合法字符**，标准 URL 中的空格必须被转义为 `%20`（或 `+`）。这意味着明文空格绝对不会出现在浏览器底层抓取的 URL 原文里，因此使用空格做分隔符**同样具有 100% 的技术严谨度，不会产生字符冲突**。
**最终结论与实现方案：**
决定采用 **竖线 `|`** 作为多个关键词的分隔符。
- **兼容性：** 为了提供更好的输入体验，系统会同时兼容处理英文竖线 `|` 和中文竖线 `｜`。当用户在输入框打出中文竖线时，代码在保存前会自动将其转换为英文竖线。
- **匹配逻辑：** 在后台拦截匹配时，将关键词字符串按照英文竖线 `|` 进行切分，然后去除每个关键词首尾的空格（trim），过滤掉空字符串。**必须要所有非空关键词都同时命中 URL（即 AND 逻辑）**，才判定匹配成功。这更符合用户在一个规则里组合多个关键词来精确定位网页的实际需求。
- **界面提示：** 在前端交互界面，提示用户“支持多关键词，请用 | 隔开”。

## 3. 待改动梳理（代码实现指南，暂不修改）

为了满足上述需求，后续在代码中需要进行的改动大致包含以下两部分：

### 3.1 核心匹配逻辑改动（`js/background.js` 或匹配模块）
1. 拦截 URL 进行关键词匹配时，不再直接判断 `url.includes(keyword)`。
2. 将保存的 `keyword` 字符串按照竖线 `|`（自动兼容中文竖线 `｜`）进行拆分：`keyword.split('|')`。
3. 去除拆分后每一项的首尾空格并过滤掉空字符串。
4. 使用 `.every()` 方法遍历检查：必须确保 URL 中包含了拆分后的每一个非空关键词，才返回匹配成功。同时需要记录命中的单条正则用于后续的标题文字替换，防止原长文本正则匹配失败导致替换回退为整个 URL。

### 3.2 界面与交互改动（`options.html`, `js/popup.js`, `messages.json` 等）
1. 当用户选择 "Keyword" 匹配模式时，输入框的 `placeholder` 需要修改，以提示用户支持多关键词。例如改为："支持多个关键词，请用 | 隔开"。
2. 在保存规则前（`setTitle`），增加输入规范化预处理：将中文竖线 `｜` 全局替换为英文竖线 `|`，避免误匹配。
